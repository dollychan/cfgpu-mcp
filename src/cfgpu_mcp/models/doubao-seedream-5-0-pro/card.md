# Doubao Seedream 5.0 Pro

Seedream 5.0 Pro 是字节跳动发布的最新图像创作模型，将图像创作推进到可控生产的新阶段。本次更新的主要亮点是**编辑更可控、生产更落地、效果更自然**。模型为同步图像生成模型，支持文生图、单图生图、多图生图（2–10 张参考图生成单张图片）。

## 基本信息

| 属性 | 值 |
|------|-----|
| 任务类型 | image |
| CFGPU 模型 ID | `doubao-seedream-5-0-pro` |
| 同步/异步 | 同步（`is_async: false`，POST 响应即返回结果） |
| 能力标签 | text_to_image, image_to_image, multi_image_fusion, region_edit |
| 成本档位 | 2/5 |
| 速度档位 | 3/5 |

## 价格

| 条件 | 计费项 | 价格 |
|------|--------|------|
| 分辨率 (0, 1K] | 统一计价 | 0.4 元 / 张 |
| 分辨率 (1K, 无限] | 统一计价 | 0.8 元 / 张 |

## 能力说明

| 能力 | 说明 |
|------|------|
| **text_to_image** | 纯文本生成单张图像 |
| **image_to_image** | 单张参考图 + 文本生成图像 |
| **multi_image_fusion** | 多张参考图片（2–10）+ 文本提示词生成单张图片 |
| **region_edit** | 按用户圈的区域做局部编辑；坐标随 prompt 内嵌，见下方「区域编辑」 |

### 不支持的能力

- ❌ **组图生成**（`sequential_image_generation` 不可用；模型仅生成单张图片）
- ❌ **联网搜索**（不支持 `tools.type: web_search`）
- ❌ **流式输出**（不支持 `stream: true`）

> 如需组图、联网搜索或流式输出，请使用 `doubao-seedream-5-0-lite`。

## 参数说明

### 核心参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| prompt | string | ✓ | - | 图像描述，支持中英文 |
| model | string | ✓ | - | 模型 ID：`doubao-seedream-5-0-pro` |

### 尺寸参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| size | string | - | 1024x1024 | 生成图像尺寸，两种方式见下方详细说明 |

支持以下两种指定方式，**不可混用**：

#### 方式 1 — 精确像素（宽 x 高）

直接指定生成图像的宽高像素值。

| 项 | 取值 |
|----|------|
| 默认值 | `1024x1024` |
| 总像素取值范围 | [921600, 4624220]，即 [1280x720, 2048x2048×1.1025] |
| 宽高比取值范围 | [1/16, 16] |
| 格式 | `<宽>x<高>`，如 `2048x1024` |

> 说明：总像素是对单张图宽度和高度的像素乘积限制，而非对宽度或高度单独值的限制。需同时满足总像素范围和宽高比范围。

**有效示例**：`2048x1024` — 总像素 2,097,152，在 [921600, 4624220] 内；宽高比 2，在 [1/16, 16] 内。

**无效示例**：`512x512` — 总像素 262,144，低于 921,600 下限。

#### 方式 2 — 分辨率档位

指定分辨率档位，并在 prompt 中用自然语言描述图片宽高比、图片形状或图片用途，由模型判断生成图片大小。

| 档位 | 说明 |
|------|------|
| 1K | 档位原样上行，模型按 prompt 自行判断宽高比 |
| 1.5K | 同上。**与 1K 同价且效果更好**，优先于 1K |
| 2K | 映射成精确像素，对照表见下方 |

> **为什么 1K / 1.5K 不映射成像素**：Pro 的价格在 1K 处分档（(0,1K] 0.4 元、
> (1K,∞] 0.8 元），而官方明确写着 1.5K 与 1K 同价——这只有在**档位名本身是计价依据**
> 时才成立（1.5K 的像素数远在上一档里）。把这两档展开成精确像素，等于为了一个模型
> 本来就会从 prompt 里推断的宽高比，把这次调用的价格翻一倍。代价是这两档下
> `aspect_ratio` 只是建议：请在 prompt 里用自然语言描述所需的画幅。

采用方式 2（2K）时映射的宽高像素值。**注意与 Seedream 5.0 lite / 4.5 / 4.0 的同名
档位不是同一张表**（如 2K 16:9：Pro 是 2816x1584，lite 是 2848x1600）：

| 分辨率 | 宽高比 | 宽高像素值 |
|--------|--------|------------|
| 2K | 1:1 | 2048x2048 |
| 2K | 4:3 | 2368x1776 |
| 2K | 3:4 | 1776x2368 |
| 2K | 16:9 | 2816x1584 |
| 2K | 9:16 | 1584x2816 |
| 2K | 3:2 | 2496x1664 |
| 2K | 2:3 | 1664x2496 |
| 2K | 21:9 | 3136x1344 |

### 参考图参数

## 区域编辑（`region_edit`）

支持通过坐标、框选精确指定编辑位置。**入参只需「待编辑图片 + prompt」——没有任何
结构化坐标槽**，坐标以 `<bbox>` 标签内嵌在 prompt 文本里，endpoint 与响应结构都不变。

统一 schema 侧照常传 `regions`，adapter 负责换算与织入：

| 层 | 形态 |
|----|------|
| 统一 schema (`regions[].box`) | 归一 `[0, 1]` float，`[x1, y1, x2, y2]`，x 先序，左上原点 |
| 落到 prompt | `<bbox>x1 y1 x2 y2</bbox>`，`[0, 999]` 整数格索引 |

换算规则（**含尾格**）：左/上取 `floor(v*1000)`，右/下取 `ceil(v*1000)-1`。`999` 是
1000 等分的最后一格的**索引**而不是图片右边缘的坐标，两边同样取整会让整图框
`[0,0,1,1]` 差一格，且这个差一会跟着每次编辑往下漂。

### prompt 占位符

位置在这条方言里**有语义**——「把图1 `<bbox>…</bbox>` 的主体放到图2 `<bbox>…</bbox>`
位置」和两个框互换不是同一个请求——而只有调用方知道自己的句子，所以由调用方用
`[[…]]` 标出每个框该落在句子的哪里：

| 写法 | 指什么 |
|------|--------|
| `[[标记1]]` | 某个框（本次调用内该名字唯一时） |
| `[[m_a1#标记1]]` | 某个框（跨图重名时的限定写法；`m_a1` 来自 `image_refs`） |
| `[[m_a1]]` | 整张图，渲染成 `图1` 之类的 1-based 序数 |

- **裸名字跨图重名 → 硬报错**并列出限定写法。取第一个的后果是**在另一张图上编辑**：
  有产出、要计费、看着还挺合理。
- **没被引用的区域不会被丢掉**，会追加成一段「参考区域：图1 `<bbox>…</bbox>`」结构化
  后缀。丢一个框不会报错，只会产出一张整图重绘的图并计费。
- **`[[m_a1]]` 而不是手写「图1」**：图片槽的顺序会随调用重排，写死的序数会静默指向
  另一张图。

### 标记名和 `note` 不会进入 prompt

Pro 是生图模型，prompt 里出现「标记1」这几个字有被**画进结果图**的风险，而标记只是位
置指引。它只拿到坐标。视觉理解侧（`qwen3.6-plus`）相反：只读不画，所以名字和 `note`
都给，回答也会用标记名指代。

### 示例

```json
{
  "model": "doubao-seedream-5-0-pro",
  "reference_images": ["https://example.com/room.jpg"],
  "image_refs": ["m_a1"],
  "regions": [
    {"image_index": 0, "box": [0.179, 0.283, 0.796, 0.986], "label": "标记1"}
  ],
  "prompt": "把[[标记1]]那只杯子换成一只青花瓷茶壶，保持原有透视，其余不变"
}
```

落到 upstream 的 prompt 文本：

```
把<bbox>179 283 795 985</bbox>那只杯子换成一只青花瓷茶壶，保持原有透视，其余不变
```

### 不支持时会怎样

`regions` **永不静默忽略**。传给没有 `region_edit` 的模型是硬错误，文案给两条出路：
换用支持的模型，或先用 `understand_vision(images=[...], regions=[...])` 问清标记里是
什么，再把答案改写成纯自然语言的 prompt 重新调用。

## 约束与限制

| 限制项 | 值 |
|--------|-----|
| 组图生成 | ❌ 不支持（`sequential_image_generation` 不可用） |
| 联网搜索 | ❌ 不支持 |
| 流式输出 | ❌ 不支持 |
| 参考图数量上限 | 10 张（多图生图需 2–10 张） |
| 总像素范围 | [921600, 4624220]（约 [1280x720, 2048x2048×1.1025]） |
| 宽高比范围 | [1/16, 16] |
| 分辨率档位 | 1K、1.5K、2K（3K/4K 超出总像素上限，会被拒绝而不是静默降档） |
| 单图区域数上限 | 无（`regions` 不限个数） |
| 输出图片链接有效期 | 24 小时 |

## 错误处理

| 错误类型 | 原因 | 建议 |
|----------|------|------|
| content_blocked | Prompt 或图片包含敏感内容 | 修改内容，避免敏感词 |
| invalid_params | 参数超出范围（如 size 总像素超出 [921600, 4624220]） | 检查 size、image 数量是否符合约束 |
| image_download_failed | 参考图 URL 无法访问 | 确保 URL 公网可访问 |
| quota_exceeded | 配额不足 | 检查账户余额 |

## 与统一 Schema 的映射

| 统一 Schema 字段 | Seedream Pro 字段 | 映射说明 |
|------------------|-------------------|----------|
| prompt | prompt | 直接映射 |
| aspect_ratio | size（方式 1） | 组合进 size 像素值；或在方式 2 作为提示词辅助，模型自动判断 |
| resolution | size | 1K/2K 档位映射；1K 透传为 `"1K"`（无固定像素表），2K 映射为精确像素 |
| reference_images | image | URL 数组；单张为 string，多张为 array（2–10） |
| n | — | Pro 仅支持 n=1；n>1 会报错拒绝（不支持组图） |
| regions | prompt 内嵌 `<bbox>` | 归一 `[0,1]` → `[0,999]` 格索引，见「区域编辑」 |
| image_refs | — | 只用于解析 prompt 里的 `[[句柄]]`，不上行 |
| watermark | watermark | 直接映射 |
| model_specific | - | 可传入 response_format 等额外字段 |
